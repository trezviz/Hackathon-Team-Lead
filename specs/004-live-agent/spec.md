# Feature Specification: Live Agent (Real AI)

**Feature Branch**: `004-live-agent`

**Created**: 2026-09-21
**Status**: Approved

## Product

Replace the offline, scripted UI simulation with a live local agent: a small Python server that reads the real repository, calls a real LLM (Anthropic Claude or Google Gemini) to plan and implement one small approved change, and runs real verification checks.

## User Scenarios & Testing

### User Story 1 - Real project map (Priority: P1)

The reviewer sees and searches the actual files in the repository, not a hardcoded list.

**Acceptance Scenarios**:

1. **Given** the server is running, **When** the UI loads, **Then** the project map matches the real repository file listing.

### User Story 2 - Real AI plan (Priority: P1)

The reviewer enters a task and constraints and receives a plan generated by Claude from the real file list, not a canned template.

**Acceptance Scenarios**:

1. **Given** an AI key (`ANTHROPIC_API_KEY` or `GEMINI_API_KEY`/`GOOGLE_API_KEY`) is configured, **When** a plan is requested, **Then** the server calls that provider's API and returns its plan (summary, relevant files, steps, verification, risks).
2. **Given** no AI key is configured, **When** a plan is requested, **Then** the server returns a clear error instead of a fabricated plan.

### User Story 3 - Real, scoped file edit (Priority: P1)

After approval, the reviewer picks one file from the plan's relevant files; the agent asks Claude to rewrite it and writes the result to disk.

**Acceptance Scenarios**:

1. **Given** an approved plan, **When** the reviewer selects a target file and completes the task, **Then** the server only writes to that file, only if it is one of the plan's relevant files, and only if it is not a sensitive filename.
2. **Given** the AI output contains a value that looks like a real secret or token, **When** the edit is applied, **Then** the write is blocked and reported as an error.

### User Story 4 - Real checks and report (Priority: P1)

The reviewer selects checks and receives a report built from real check results and a real diff, not scripted text.

**Acceptance Scenarios**:

1. **Given** an applied change, **When** checks are run, **Then** scope, secret-scan, and Markdown/link checks execute against the actual file content and the report lists their real pass/fail results and the real diff.

## Requirements

- **FR-001**: Serve the real repository file list and support substring search, excluding VCS/tooling directories.
- **FR-002**: Generate the plan via a real call to the configured LLM API (Anthropic Messages API or Google Gemini generateContent API), constrained to the AGENTS.md rules and the real file list.
- **FR-003**: Require explicit approval (server-side) before any file may be edited or checked.
- **FR-004**: Restrict edits to a single file drawn from the plan's relevant files; reject sensitive filenames and non-text/non-approved extensions.
- **FR-005**: Scan AI output for secret-shaped strings before writing to disk; block the write if found.
- **FR-006**: Run real checks (scope, secret-scan, Markdown structure/local-link validation) against the actual file content.
- **FR-007**: Report real changed files, the real unified diff, real check results, and real remaining risks.
- **FR-008**: Never fabricate a successful plan, edit, or check result when the AI call fails or the API key is missing — return an honest error instead.
- **FR-009**: Never expose the API key to the browser, in logs, or in error messages.
- **FR-010**: Support either Anthropic or Google Gemini as the AI provider, selected automatically from which key is configured (or forced via `AI_PROVIDER`).

## Success Criteria

- **SC-001**: All six Hackathon Tech Lead capabilities are demonstrated with real data (real files, real AI plan, real edit, real checks, real report).
- **SC-002**: Running the server without an API key never produces a fabricated AI result.
- **SC-003**: An edit outside the approved plan's relevant files, or targeting a sensitive filename, is rejected by the server.
